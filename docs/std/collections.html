Package collections

import "std/collections"

#Overview

BloomFilter[T]: a probabilistic set.

Answers "is this element in the set?" with "definitely not" or "probably yes", using a bit array and several hash functions, in far less memory than storing the elements. Elements can't be removed or listed. Useful to skip expensive lookups (disk, network) for things that aren't there.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Bloom_filter

std/collections — Collections beyond the prelude's [T], #[T], and #[K: V]: Deque, Queue, BitSet, PriorityQueue, StringInterner, and BTreeMap.

DisjointSet: union-find over the integers 0..n.

Tracks a partition of elements into groups, with two near-constant-time operations: merge the groups of two elements (union), and find which group an element is in (find). Useful for connected components, Kruskal's minimum spanning tree, and grouping equivalent things.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Disjoint-set_data_structure
  • https://cp-algorithms.com/data_structures/disjoint_set_union.html

FenwickTree: a binary indexed tree for prefix sums.

An array of numbers where both "add x to element i" and "sum of elements 0..i" take O(log n), in a single flat array. Useful for running totals, frequency counts and ranks, and range-sum queries over data that keeps changing.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Fenwick_tree
  • https://cp-algorithms.com/data_structures/fenwick.html

Graph[N, E]: nodes connected by edges, as adjacency lists.

Nodes with data of type N and edges with data of type E (weights, labels), each node keeping a list of its neighbors. The base for breadth- and depth-first search, shortest paths, topological sort, and dependency resolution (build systems, package managers).

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Adjacency_list

IntervalTree[T]: a set of intervals searchable by overlap.

Stores intervals (lo..hi) so that "which intervals contain this point?" or "which overlap this range?" takes O(log n + matches). Useful for calendars and scheduling, genome ranges, text editor decorations, and collision broad phases.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Interval_tree

LinkedList[T]: a doubly linked list.

Each element lives in its own node that points to the next and previous nodes, so inserting or removing at a known position takes O(1) time without shifting anything. Useful for queues and LRU caches that splice elements around, and as a classic exercise in ownership: in Lowlight the nodes have to be owned somewhere (a list of nodes addressed by index, a Pool, or an Arena).

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Doubly_linked_list
  • https://opendatastructures.org/ods-python/3_2_DLList_Doubly_Linked_Li.html

LruCache[K, V]: a bounded cache that evicts the least recently used entry.

A map with a fixed capacity: when it is full, inserting evicts the entry that was used longest ago. Usually a hash map plus a linked list ordered by use, so both lookup and eviction are O(1). Useful for memoizing expensive results, caching files or responses, and bounding memory.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Cache_replacement_policies

Multiset[T]: a set that counts repeated elements (a bag).

Like #[T], but each element has a count: adding an element twice keeps two of it. Usually a map from element to count. Useful for word and letter counts, histograms, inventories, and checking whether two lists hold the same elements regardless of order.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Multiset

RingBuffer[T]: a fixed-capacity circular buffer.

A buffer of fixed size whose end wraps around to its start. Once full, pushing a new element overwrites the oldest one (or is refused). Unlike Deque, it never grows, so memory use is bounded: good for the last N log lines, audio and network streams, and producer/consumer queues.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Circular_buffer

Rope: a string stored as a tree of pieces.

A large string held as a binary tree of smaller strings, so inserting or deleting text in the middle, concatenating, and splitting take O(log n) instead of copying the whole string. Useful for text editors and anything that edits very large strings.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Rope_(data_structure)

SegmentTree[T]: range queries over an array.

A tree over an array where each node summarizes a range (its sum, minimum, maximum, ...), so a query over any range and an update to any element both take O(log n). More general than a Fenwick tree. Useful for range minimum/maximum queries and interval statistics.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Segment_tree
  • https://cp-algorithms.com/data_structures/segment_tree.html

SkipList[K, V]: an ordered map built from linked lists.

A sorted linked list with extra "express lane" lists above it that skip over elements, chosen at random. Search, insert, and remove take O(log n) on average, like a balanced tree, with simpler code. Useful as an ordered map and in concurrent settings; an alternative to BTreeMap.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Skip_list
  • https://opendatastructures.org/ods-python/4_Skiplists.html

Trie: a prefix tree of strings.

Stores strings by their characters, one tree level per character, so all strings sharing a prefix share a path. Finding every stored string that starts with a prefix takes time proportional to the prefix. Useful for autocomplete, spell checking, routing tables, and keyword matching.

I'm implementing this one myself. Please leave this file as is.

Further reading:

  • https://en.wikipedia.org/wiki/Trie
  • https://cp-algorithms.com/string/aho_corasick.html

structdefine BTreeMap[K: Comparable, V] structsource

A map that keeps its keys in sorted order, for ordered iteration, the smallest and largest keys, and range queries. A B-tree, so lookups, inserts, and removals take O(log n).

Use the prelude's #[K: V] when order doesn't matter: it is faster and needs Hashable keys rather than Comparable ones.

#Example

let scores = collections.BTreeMap[string, int].new()
scores.insert("bea", 7)
scores.insert("ada", 9)
assert(scores.first()?.key == "ada")
assert(scores.get("bea") == 7)

structdefine BitSet structsource

A set of non-negative integers stored as one bit each, for dense sets of small numbers (ids, indexes, flags). It grows to fit the largest member.

#Example

let seen = collections.BitSet.new()
assert(seen.insert(3))
assert(not seen.insert(3))
assert(seen.contains(3) and not seen.contains(4))

structdefine PriorityQueue[T] structsource

A priority queue: PriorityQueue.pop always returns the element that comes first in the queue's order. A binary heap, so push and pop take O(log n).

The order is a closure order(a, b) that is negative when a should come out before b, positive when after, and zero when either may. min_first and max_first build the usual orders for Comparable elements.

#Example

let tasks = collections.PriorityQueue[Task].new(cl(a: Task, b: Task) int: b.urgency - a.urgency)
let small = collections.min_first[int]()
small.push(5)
small.push(1)
assert(small.pop() == 1)

structdefine StringInterner structsource

Gives each distinct string a small integer id, so repeated strings (identifiers in a compiler, tags, words) can be stored and compared as ints. Ids count up from 0 in the order strings are first interned, and never change.

#Example

let names = collections.StringInterner.new()
let a = names.intern("alpha")
assert(names.intern("alpha") == a)
assert(names.name_of(a) == "alpha")
