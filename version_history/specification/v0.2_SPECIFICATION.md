# Lowlight Language Specification (Draft v0.2)

Lowlight is a low-level, strictly-typed, expression-oriented systems programming language featuring deterministic manual memory management with Rust-like ownership, targeted control-flow unwinding, and direct transpilation to C (and subsequently native executables).

---

## 1. Core Philosophy & Design Principles

1. **Low-Level & Transparent**: Directly maps to C types, stack frames, and explicit pointers. Zero garbage collection, zero hidden runtime overhead.
2. **Strict Single Ownership & Borrowing**: Heap resources have a single owner. Passing moves ownership; borrowing uses explicit references (`&` for immutable, `&-` for mutable).
3. **Expression-Oriented by Default**: Almost everything is an expression that produces a value. Only declarations (`let`, `bind`, `define`), assignments (`=`), and unwinds (`<-`), along with `void` functions/blocks/loops, are non-value statements. Functions take a single expression (or block expression) as their body.
4. **Strict Delimiter Roles**:
   * `{}` is **strictly reserved** for executable block expressions.
   * `[]` is **strictly reserved** for compound data structures and type definitions (as well as collection indexing and destructuring).
   * `()` is used for parameter lists, grouping, and function calls.
5. **Compile-Time Safety Over Runtime Checks**: Non-value blocks cannot be assigned, all execution branches in value-producing contexts must exhaustively produce values, and null pointers are eliminated via typed Optionals (`?T` / `name?`).

## 2. Lexical Structure & Statements

### 2.1 Semicolons & Newlines
* Semicolons (`;`) are **optional**.
* A newline acts as a statement separator.
* Multiple statements on the same line must be separated by semicolons:
  ```
  let a = 1; let b = 2
  ```

### 2.2 Comments
* Single-line comments begin with `//`:
  ```
  // This is a comment
  ```

## 3. Variable Declarations & Mutability

### 3.1 `let` vs `bind`
* **`let` (Mutable)**: Declares a variable that can be reassigned or mutated.
  ```
  let x = 10
  x = 20
  ```
* **`bind` (Immutable)**: Declares a constant binding that cannot be reassigned.
  ```
  bind max_size = 100
  max_size = 200 // COMPILE ERROR: cannot reassign a bound variable
  ```

### 3.2 Deep vs Shallow Immutability
* **Primitives & Stack Structs (Deeply Immutable)**:
  A `bind` struct cannot have its fields modified:
  ```
  bind pt = Point[x: 1, y: 2]
  pt.x = 5 // COMPILE ERROR: `pt` is deeply immutable
  
  let mutable_pt = Point[x: 1, y: 2]
  mutable_pt.x = 5 // OK
  ```
* **Heap Collections (Shallow Immutability)**:
  For Maps, Sets, and Vectors, `bind` freezes the *binding* (it cannot be reassigned to a different collection), but permits element insertion and removal via methods:
  ```
  bind cache = #["a": 1]
  cache.insert("b", 2) // OK: interior collection mutation
  cache = #["c": 3]    // COMPILE ERROR: cannot reassign binding
  ```

### 3.3 Function Variables
Functions can be declared with `let` to create mutable function pointers:
```
bind static_add = (a int, b int): int a + b  // Emits static C function
let current_op = static_add                  // Emits C function pointer
current_op = (a int, b int): int a * b       // Reassigned!
```

## 4. Primitive Types & Literals

### 4.1 Integers & Floats
* **`int`**: Default signed integer, aliased to `i64` (`int64_t` in C).
* **Compile-Time Literal Sizing**: Numeric literals automatically infer the smallest fitting type when inferring types.
* **Fixed-Width Integers**:
  * Signed: `i8`, `i16`, `i32`, `i64`
  * Unsigned: `u8`, `u16`, `u32`, `u64`
* **Floats**: `f32`, `f64` (default `float` is `f64`).
* **Booleans**: `bool` (`true` or `false`).
* **Characters**: `char` (32-bit Unicode code point).

### 4.2 Strings & Interpolation
* **`string` (Owned Dynamic String)**:
  Heap-allocated, dynamically resizable UTF-8 text with length and capacity. Automatically dropped at scope exit:
  ```
  let s = "Hello" // type: string
  ```
* **`&string` (Borrowed String View / Slice)**:
  A zero-cost read-only reference into a string or static binary literal.
* **`&-string` (Borrowed Mutable String)**:
  A mutable reference allowing in-place modification without reallocating:
  ```
  bind append_tag = (s &-string) {
      s.push(" [TAG]")
  }
  ```
* **Interpolation**:
  * `$ident` for single non-optional variable names: `"Hello, $name!"` (Because optional wrappers must be unwrapped before use, bare `$ident` never includes a trailing `?`; in `"Are you $ready?"`, `$ready` is interpolated and `?` is literal text.)
  * `${expr}` for inline expressions (including optionals with fallbacks): `"Total: ${price * count}"`, `"User: ${user?.name ?? "Guest"}"`
  * Escaped literal dollar sign: `\$` or `$$`

## 5. Memory Management & Borrowing

### 5.1 Single Ownership & Move Semantics
* Scalar/primitive types (`int`, `float`, `bool`, `char`) implement copy semantics.
* All heap-allocated resources (vectors, maps, sets, strings, heap structs) have a **single owner**.
* Assigning an owned variable or passing it by value **moves** ownership. The source variable becomes invalid at compile time:
  ```
  let a = [1, 2, 3]
  let b = a // Ownership moved to `b`; `a` can no longer be used!
  ```

### 5.2 Borrowing Syntax: `&` and `&-`
To use data without transferring ownership, references are borrowed:
* **Immutable Borrow (`&T`)**: Shared, read-only view. Multiple readers allowed concurrently.
* **Mutable Borrow (`&-T`)**: Exclusive, read-write view. Exactly one writer allowed; no other readers or writers.

#### Mandatory Call-Site Annotation & Method Auto-Borrowing:
* **Direct Function Calls**: The caller must explicitly pass `&-` when supplying a mutable borrow:
  ```
  bind push = (list &-[int], val int) { ... }

  let my_list = [1, 2, 3]
  push(&-my_list, 4) // `&-` required at call site for transparency
  ```
* **Method Calls**: Calling a method via dot syntax (`pt.translate(5, 5)`) automatically borrows the receiver (`pt`) as `&` or `&-` according to the method's `self` parameter. Calling the method using its full namespaced path (`Point.translate(&-pt, 5, 5)`) requires explicit `&-` at the call site.

## 6. The Optional System & Non-Value Safety

### 6.1 No Raw Nulls
Raw `NULL` pointers do not exist. Absence of a value is modeled safely through **Optionals** (`?T`).

### 6.2 Optional Types (`?T`) & Variable-Name Optionals (`name?`)
* The underlying optional type is written `?T` (e.g., `?int`, `?User`).
* **Flattening**: Nested optionals `?(?T)` automatically flatten to `?T`. Optional types may be stored inside collections and other types (e.g., `[?int]`, `#[string: ?int]`).
* **Mandatory `?` Identifier Suffix**: A variable can hold an optional value (`?T`) **if and only if** its identifier ends with a `?`. Conversely, a variable without a `?` suffix is guaranteed never to hold an optional:
  ```
  let user? = find_user(id) // type: ?User
  let count?: ?int = none   // Explicitly typed optional initialized to none
  ```
* **Distinct Identifiers**: `user` (type `User`) and `user?` (type `?User`) are two distinct identifiers.

Under the hood in C, `?T` transpiles to a tagged struct:
```c
typedef struct {
    bool has_value;
    T value;
} Opt_T;
```

### 6.3 Smart Narrowing, Chaining & Fallbacks
1. **Presence Check & Borrowed Unwrapping in `if`**:
   * `if (user?)` always checks for the **presence** of a value (`has_value`), even if the inner type is `bool` (`if (flag?)`). The optional wrapper must be handled before interacting with the inner value.
   * Inside an `if (user?)` branch, the unwrapped value is automatically bound to the non-optional identifier `user` as a **borrow** of `user?` (preventing `user?` from being mutated to `none` while `user` is borrowed in that scope). If an outer `user` exists in the enclosing scope, it is shadowed inside the `if` branch:
     ```
     if (user?) {
         print(user.name) // `user` borrows the unwrapped value of `user?`
     }
     ```
2. **Dot Chaining (`.`)**:
   The `.` operator works uniformly on both non-optional and optional values. Accessing a field or method on an optional (`user?.name`, `u?.address?.city`, or `find_user(id)?.name`) short-circuits to `none` (producing `?FieldType`) if the base value is `none`.
3. **Fallback Operator (`??`)**:
   Unwraps an optional if present, or evaluates the right-hand fallback (which may be a default value or an unwind statement):
   ```
   let display_name = user?.name ?? "Guest"
   bind verified_user = user? ?? func <- none
   ```

### 6.4 Non-Value Block Safety
A block expression `{ ... }` produces a value if and only if its final statement is an expression or an early exit yielding a value.
* Attempting to assign a block (or `void` function/loop) that ends in a statement without a value is a **Compile-Time Error**:
  ```
  let x = {
      let a = 1
      let b = 2
  } // COMPILE ERROR: Block does not evaluate to a value
  ```

## 7. Compound Data Structures

### 7.1 Vectors vs Stack Arrays
* **Dynamic Heap Vector (`[T]`)**:
  Heap-allocated, dynamically growable:
  ```
  let v = [1, 2, 3] // type: [int]
  v.push(4)
  ```
* **Fixed Stack Array (`[N: T]`)**:
  Allocated directly on the C stack frame. Zero heap overhead:
  ```
  let s = [3: 1, 2, 3] // Stack array of 3 elements (type: [3: int])
  let buffer = [100: 0] // Repeated initialization: 100 zeroes on stack
  ```

### 7.2 Maps & Sets
* **Set Literal (`#[T]`)**:
  ```
  let visited = #[1, 2, 3]
  visited.insert(4)
  if (visited.has(2)) { ... }
  visited.remove(1)
  ```
* **Map Literal (`#[Key: Value]`)**:
  ```
  let ages = #["Alice": 30, "Bob": 25]
  ages.insert("Charlie", 35)
  ages["Diana"] = 28 // Shorthand for insert
  ```
* **Map Lookup Returns Optionals**:
  Indexing a map always evaluates to `?Value` (with `?(?T)` automatically flattened to `?T`):
  ```
  let age? = ages["Alice"]
  let actual_age = ages["Alice"] ?? 0
  ```

### 7.3 Trailing Comma Rule
* **Multiline comma-separated lists** require a trailing comma on the final line:
  ```
  let g = [
      1,
      2,
      3, // Required!
  ]
  ```
* Inline lists have optional trailing commas: `[1, 2, 3]` or `[1, 2, 3,]`.

## 8. Type Definition System (`define`)

All user-defined types use the unified `define <Name> <Kind> [ ... ]` syntax.

### 8.1 Structs
```
define Point struct [
    x: int,
    y: int,
]

// Instantiation:
let pt = Point [
    x: 10,
    y: 20,
]

// Field access:
let px = pt.x
```

### 8.2 Enums & Tagged Unions
Variants can be unit markers or carry compound data:
```
define Shape enum [
    Circle [ radius: float, ],
    Rectangle [ width: float, height: float, ],
    Point,
]
```

### 8.3 Interfaces
```
define Printable interface [
    to_string: (): string,
]
```
* **Implicit Implementation (Structural / Duck Typing)**:
  Any type that defines the methods declared in an interface automatically implements that interface.
* **Universal Applicability**:
  Structs, enums, custom types, and built-in types (`int`, `string`, etc.) can all implement interfaces.
* **C Fat Pointer Representation**:
  Transpiles to `{ void* data; const VTable* vtable; }`. Zero heap overhead when passed as `&Printable`.

### 8.4 Type Aliases
```
define UserID int
define Port u16
```

## 9. Namespaced Methods

Functions are attached to types using namespaced declarations. The first parameter explicitly binds `self`:

```
// Immutable method borrow (returns float)
bind Point.length = (self &Point): float {
    sqrt(self.x * self.x + self.y * self.y)
}

// Mutable method borrow (requires `let` struct; void return)
bind Point.translate = (self &-Point, dx int, dy int) {
    self.x = self.x + dx
    self.y = self.y + dy
}

// Called using dot syntax (auto-borrows `pt`):
let len = pt.length()
pt.translate(5, 5)

// Or called via explicit type namespace (requires explicit `&` / `&-`):
Point.translate(&-pt, 5, 5)
```

### 9.1 Extending Built-in Types
Built-in types can be extended with methods to satisfy interfaces:
```
bind int.to_string = (self &int): string {
    "${self}"
}

// `int` now automatically implements `Printable`!
```

## 10. Functions & Expression Bodies

A function takes **exactly one expression** (or block expression) as its body.
* **Value-Returning Functions**: Must specify their return type with `:Type` or `:?Type` after the parameter list.
* **Void Functions**: Functions that only perform side effects or mutate `&-` arguments omit the `:Type` annotation and do not return a value.

```
bind add = (a int, b int): int a + b

bind add_with_block = (a int, b int): int {
    let sum = a + b
    sum // evaluates to sum
}
```
Both are functionally identical because a block `{}` is an expression.

## 11. Control Flow & Unwinding

### 11.1 If-Expressions
`if` is an expression yielding a value:
```
let result = if (c == 3) 4 else 3

let complex = if (c == 3) {
    log("Matched")
    4
} else {
    3
}
```

### 11.2 Unified `for` Loops
The unified `for` expression handles all iterations:
```
// Ranges
for (i in 0..10) { ... }

// Collections
for (item in my_list) { ... }

// Maps
for (k, v in my_map) { ... }

// Conditionals (While equivalent)
for (count < 10) { ... }

// Infinite Loops
for (true) { ... }
```

#### Loop Expression Evaluation:
* **With `else` clause**: If the loop exhausts without breaking, it evaluates to the `else` expression (returns guaranteed `T`):
  ```
  let found = for (x in list) {
      if (x > 10) for <- x
  } else {
      0
  }
  ```
* **Without `else` clause**: If the loop is used as a value expression and exhausts without breaking, it evaluates to `none` (returns `?T`):
  ```
  let found? = for (x in list) {
      if (x > 10) for <- x
  }
  ```
* **As a statement**: If a `for` loop is not assigned or used as a value, any result is discarded (or it runs as a `void` loop).

### 11.3 Targeted Unwinding (`target <- value`)
`<-` is a statement (not a general expression) that unwinds nested `{ ... }` blocks directly to a target:

| Syntax | Target | Description |
| :--- | :--- | :--- |
| `<- value` / `<-` | Immediate Block `{}` | Exits the nearest enclosing `{ ... }` block, yielding `value` (or no value in a `void` block). |
| `if <- value` | Nearest `if` | Unwinds all blocks up to the nearest enclosing `if`, making that `if` evaluate to `value`. |
| `for <- value` / `for <-` | Nearest `for` loop | Breaks out of the nearest loop, evaluating the loop to `value` (or exiting a `void` loop). |
| `next <- value` / `next <-` | Current loop iteration | Ends the current iteration of the nearest `for` loop and advances to the next iteration. |
| `func <- value` / `func <-` | Nearest Function | Unwinds all blocks and immediately returns `value` (or returns `void`) from the current function, method, or lambda. |
| `func_name <- value` | Named Function | Unwinds all blocks and immediately returns `value` from the lexically enclosing `func_name`. |
| `label <- value` | Labeled block / loop | Unwinds to the specified label (`outer: for (...)`). |

#### Unwind Rules & Restrictions:
1. **No Cross-Function Jumps**: An unwind (`<-`) can **never** cross a function or lambda boundary. Attempting to unwind an outer function from inside a nested function or lambda is a **Compile-Time Error**.
2. **Valid Positions for `<-`**:
   * As a standalone statement (including as the body of an `if` branch or `match` arm).
   * Immediately on the right-hand side of a top-level `??` in a variable declaration or assignment:
     ```
     let b? = maybe_null()
     bind example = (): int {
         if (true) {
             let a = b? ?? if <- 0
             a
         } else {
             0
         }
     }
     ```
   * Unwinds are **not** permitted inside nested sub-expressions or function call argument lists.

#### Example:
```
bind find_even = (numbers &[int]): ?int {
    let first_even? = for (n in numbers) {
        if (n % 2 == 0) {
            for <- n // breaks loop, yields n to first_even?
        }
        if (n == 999) {
            func <- none // bails out of the entire function immediately!
        }
    }
    first_even?
}
```

### 11.4 Exhaustive Flow Check (Rule 1)
Every execution path in a value-producing block or function must yield a value. Missing returns or unhandled branches result in a **Compile-Time Error**.

## 12. Pattern Matching (`match`)

`match` is a container-free, keyword-driven expression using `when ... else`. It destructures enums, checks literals, and guarantees compile-time exhaustiveness:

```
// Matching Primitives
let label = match (status_code)
    when 200: "OK"
    when 404: "Not Found"
    when 500: {
        log("Internal server error")
        "Error"
    }
    else: "Unknown"

// Matching Enums / Tagged Unions with Destructuring
let area = match (my_shape)
    when Circle[r]: 3.14159 * r * r
    when Rectangle[w, h]: w * h
    when Point: 0.0
    else: 0.0
```

## 13. Transpilation to C Architecture

1. **Target Standard**: Clean, portable C99 / C11.
2. **Deterministic Cleanup Injection**:
   At every block exit and prior to any `target <- value` jump, the compiler emits cleanup functions for all live owned resources in that scope (`vec_free`, `map_free`, `string_free`).
3. **Tagged Unions & Optionals**:
   Transpiled as C structs containing an integer/boolean tag and a union payload.
4. **VTable Generation**:
   Static struct vtables generated for all types implementing interfaces.
