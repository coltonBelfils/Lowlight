# Lowlight / Lightweight Language — Initial Seed Sample (v0.0)

**Date:** October 16, 2026  
**Context:** Original prompt and syntax sample provided to initiate the language design process.

---

## Original Prompt & Requirements

> I want you to make a programing language. It will be compiled/transpiled to c during the compilation process and then to an executable. It should be low level, strictly typed, strictly memory managed with smart manual allocation and freeing.
>
> Here's a sample of the language to start from. There's lots of refinement and implamentation details to sort out still, but this is a rough start direction:
>
> ```
> let a = 1; // variable declation; implicit but strict type binding
> bind b = 2 // constant declation
> 
> // optional semicolon. One statement per line, or multiple with semicolon.
> 
> bind add = (a int, b int) a + b;
> 
> bind add2 = (a int, b int) {
>     a + b;
> }
> 
> // functions take in one expression for their body, that expression may be a block expression, {}, which will be a list of statements (which themselves may be expressions), so add and add to are functionally identical.
> 
> bind add3 = (a int, b int) {
>     <- a + b;
> };
> 
> // a return statement (<-) in a block expression breaks early from the block expression and the whole expression evaluates to what is returned, otherwise the block expression evaluates to the last statement in the block expression. If that statement is an expression, that value is returned, otherwise null is returned as the value.
> 
> let c = add(a, b) // a + 2
> 
> let d = add(5, if(c == 3) 4 else 3) // 5 + 4
> 
> // function literals and ifs are both expressions
> 
> let e = if(c == b + 2) 7 else 8 // e = 8
> 
> let f = if(c == b + 2) {
>     <- 7 // since this is the last statement in the block the return (<-) is optional
> } else {
>     <- 8
> } // e = 8
> 
> // the e and f assignment if expressions are essentially the same thing
> 
> let g = [1, 2, 3,] //array. All elements are strictly the same type. Final comma on the same line is optional for all data structures
> g[0] //1
> 
> let h = #[1, 2, 3] //set. All elements are strictly the same type
> 
> let i = #["a": 1, "b": 2, "c": 3] //map. All keys are strictly the same type. All elements are strictly the same type
> i["a"] //1
> 
> define j [ // struct definition
>     a: int,
>     b: int,
>     c: interface, // final comma required for multiline comma seperated lists
> ]
> 
> let k = j[ // struct instationation
>     a: 1,
>     b: 2,
>     c: 3,
> ]
> ```
>
> Run all design decisions past me. I know there will be many. Don't start on implamentation until everything is ironed out.
